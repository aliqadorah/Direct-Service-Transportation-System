## Code review and security review (two independent review rounds + author)
**Round 1 (subscription, console, lifecycle, support access) — fixed:** F1 (High) downgrade compared prices across billing cycles (an annual plan "downgraded" to a monthly higher tier) — same cycle, cheaper and no higher limit now required; F2 unpaid invoices stayed payable and an old upgrade page could switch the plan in a later period — a new checkout replaces unpaid invoices, upgrades apply only in their own period; F3 the webhook did not check the amount or currency — exact total and currency required; F4 reactivating an ended free trial made the tenant Active and free forever — refused, and reactivation never grants a free period; F5 renewal not idempotent and one failing tenant stopped the run — invoice reuse, charge keyed by invoice number, per-tenant isolation, platform lock; F6 support-session audit rows recorded 200 for refused or failed requests — the status returned is recorded; F7 anonymisation incomplete — licence, notes, custom fields, invitation e-mails, session addresses, AP/AR party and company contacts added, audit log documented as the exception (DT-134); F8 deletion e-mails before the commit — after it; F9 a credited invoice could be paid and payments could lift a staff suspension or apply to closed tenants — "PaidNotApplied"; F10 one "free" reference for all free renewals — unique per invoice, ambiguous references ignored; F11 plan-code check ignored retired plans; F13 demo trips counted, file purge race in the storage size; F14 exports from a support session.
**Round 2 (fixes and onboarding, export, erasure) — fixed:** R1 (High) an Administrator could erase an archived user of another company or an archived Owner — the user must belong to the company and Owner-level users need an Owner (SR-01); R2 (High) ids without a foreign key (journal source, posting party, lock entity) left the export as internal numbers — resolved through their type column or left empty; R3 renewal could reuse and charge a checkout invoice of the same start date — only reference-less renewal invoices are reused and an open checkout of the last day defers the renewal; R4 failed checkout pages stayed payable and payments of replaced invoices vanished — replaced as well, late payments recorded as "PaidNotApplied"; R5 the job lock could outlive its pooled connection — unpooled connection, explicit release; R6 demo seeding outside the creation transaction and racing — one transaction, one request per tenant; R7 unlimited real work in the demo company — only its six sample trips are free each month; R8 user erasure left invitation e-mails, session addresses and audit e-mails — cleared and masked; R9 context restored only in part; R10 plan resolved by a reusable code — by public id; R11 retention placeholders built from internal ids — from public ids.
**Accepted / open:** F12 pro-rating uses the current plan price, not the last amount paid (a downgrade then upgrade in the same period pays the difference again — rare, staff can credit); F15 console tenant list counts usage per tenant (≤ 200 per page; batch when measured slow); storage limit reported, not enforced (DT-128); the payment gateway, its webhook format and refunds are provider work (DEF-02).
